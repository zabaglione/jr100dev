# 絵・音・面データ

新作の素材はプロジェクト内の JSON で管理します。別作品の `assets.py` や共通のゲーム一覧をコピーして増やす必要はありません。編集後は `check`、描画を確認するときは `capture` を実行します。

## PCG を編集する

`art.json` の `sprites` は、8 個の 16×16 ドット絵です。各絵を 16 本の文字列で表し、`#` が点灯、`.` が消灯です。1 本は必ず 16 文字にします。0〜7 番が `tile(x, y, kind)` の `kind` に対応します。

雛形の割り当ては 0=床、1=壁、2=主人公、3=宝石、4=箱、5=棘、6=門、7=枠です。絵と番号の意味を変えるときは、ルールと面データも合わせます。16×16 の絵は 8×8 の PCG 文字を 4 個使うので、8 種類で 32 文字を使い切ります。余ったように見える枠にも勝手にフォントを重ねません。

タイトルは別の PCG バンクを読み込みます。`logo` は大文字英数字と空白を使う 1〜3 行、各行 1〜10 文字です。`tagline` は画面に載せる短い説明で最大 30 文字です。タイトル・ヘルプで操作を説明し、本編には盤面と判断に必要な残量を置きます。

撮影時には PNG に加えて、`build/media/play.pcg.json` などを出力します。[PCG Workbench](../../tools/pcg_editor/README.md)で現在の文字バンクと画面を観察できます。ROM 字形はこのファイルに含めません。Workbench で試した変更を採用するときは、`art.json` の元絵に反映して再ビルドしてください。生成された `build/art.json` を編集しても次のビルドで消えます。

## 描画の余白

画面は 32 列×24 行です。`tile()` は横 2 列・縦 2 行、`number()` は横 3 列を使います。右端の座標だけを見ず、描画全体が入るかを確認します。

`game.json` の `hud` は `[行, 列, "TEXT"]` の配列です。例えば `[2, 19, "STEPS"]` は 2 行目・19 列目に表示します。動く数字や条件によって変わる文字は `draw()` で描きます。0 行はタイトルと面数、21 行以降は結果・確認のために空けておくと衝突を避けられます。

## 面を増やす

`levels.json` は「面ごとのバイト配列」の配列です。各面は最大 128 個、値は 0〜255。面数は 1〜128 で、`game.json` の `levels` と一致させます。実際にはコード・データ領域の上限にも収まる必要があります。ランタイムは面の開始時にそのデータを `d` にコピーし、残りを 0 にします。

雛形では先頭 64 個が 8×8 のマップ、65 個目（`d[64]`）が開始位置、66 個目（`d[65]`）が歩数です。マップの意味は上のスプライト番号と同じです。面の形式は自分で設計できます。変更するときは `init()` の読み取り方と、クリア可能性を示すリプレイも更新します。

全作品共通の定数表を作る場合は `game.json` の `dataTables` に名前と 1〜128 バイトを指定し、`pattern[index]` のように読みます。この領域はコード側の固定データで、書き込みは禁止です。

## BGM と効果音

JR-100 は単音です。`art.json` の `music` は `[音程, 長さ, 音程, 長さ, ..., 255]` で、255 が曲の終端です。終端に来ると先頭へ戻ります。音程は 0=休符、1〜47=音階表、長さは 1〜255 の時計単位（概ね 1/60 秒）です。実際の音はエミュレーターの PCM で確認します。

`effects` は次の 4 つを定義します。形式は `[優先度, 音の数, 音程, 長さ, ...]` です。音の数とデータの組数を揃えます。大きい優先度の効果音が鳴っている間は、小さい優先度で割り込みません。

```json
{
  "SFX_MOVE": [1, 1, 18, 1],
  "SFX_USE": [2, 2, 25, 2, 32, 3],
  "SFX_WIN": [4, 3, 18, 4, 25, 4, 37, 12],
  "SFX_LOSE": [4, 3, 20, 4, 13, 6, 6, 10]
}
```

常に鳴り続ける効果音は判断音を埋もれさせます。移動は短く、成功・失敗は区別し、静かな間も作ります。公開素材は自作または利用条件を確認したものに限ります。
