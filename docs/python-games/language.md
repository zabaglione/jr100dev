# 言語と API

これは **符号なし 8 ビット整数を扱う Python DSL** です。通常の Python の処理系や標準ライブラリーを JR-100 に載せるものではありません。検査を通る構文だけを使います。

## 4 つの入口

```python
def init():
    s.score = 0
    s.player = d[64]

def act():
    if s.action == 4:
        s.player += 1

def tick():
    pass

def draw():
    number(20, 3, s.score)
```

| 関数 | 呼ばれるタイミング | 担当すること |
| --- | --- | --- |
| `init()` | 開始・次の面・再挑戦・確定したリセット | 状態と作業用配列の初期化 |
| `act()` | 操作イベントを受けたとき | 移動、決定、衝突、成功・失敗の判定 |
| `tick()` | `game.json` の `rate` に応じた時刻 | 敵、落下、時間制限などの進行 |
| `draw()` | 表示が必要なとき | 現在の状態を描く。状態を変更しない |

`rate` は約 60 Hz の時計を何回進めるかで、1〜255 です。`rate: 6` は概ね 0.1 秒間隔、255 は概ね 4.25 秒間隔です。255 でも `tick()` は呼ばれます。ターン制なら時間でルールを変える処理を書かず、実時間のゲームなら操作と時刻の進行を分けてください。描画や演出の処理時間が加わるため、実測は動画と時計で確認します。

`draw()` は何度呼ばれても同じ状態を描けるようにします。状態・配列の変更、`sound()`、`win()`、`lose()`、アニメーション待ちは禁止です。ゲームの結果は `act()` または `tick()` で確定させます。

## 状態・配列・数値

| 名前 | 用途 |
| --- | --- |
| `s.player` など任意の `s.name` | フレームをまたいで保持する 1 バイトの状態 |
| 関数内の `target` など | 関数固有の作業変数。読む前に必ず代入する |
| `b[0]`〜`b[127]`、`c[0]`〜`c[127]` | 作業用配列。開始時に 0 |
| `d[0]`〜`d[127]` | `levels.json` の該当面がコピーされる配列。不足分は 0 |
| `game.json` の `dataTables` | 1〜128 バイトの読み取り専用配列 |
| `s.action` | 1=W/上、2=S/下、3=A/左、4=D/右、5=RETURN/ボタン |
| `s.level` | 0 から始まる面番号 |
| `s.mode` | 0=タイトル、1=本編、2=面クリア、3=失敗、4=全クリア、5=ヘルプ |

`s.action`・`s.level`・`s.mode` は読み取り専用です。結果の遷移は `win()` / `lose()`、次の面や再挑戦は共通ランタイムに任せます。SPACE はランタイムがリセット確認として扱います。パッドには SPACE 相当の専用ボタンがないため、リセット開始はキーボードです。

すべての算術の途中結果が 0〜255 に戻ります。`255 + 1` は 0、`0 - 1` は 255、`(255 + 1) // 2` は 0 です。負数・小数・大きな座標を普通の Python と同じつもりで扱わないでください。`and` / `or` の値は真なら 1、偽なら 0 になります。短絡評価は維持されます。

負の配列添字は使えません。変数の添字もアクセス前に範囲を保証します。0 除算を防ぐ条件分岐も必要です。文字列は `text()` / `lose()` のリテラルに限り、画面文字は空白から `_` までの ASCII（大文字英数字と記号）です。

## 使用できる構文

- `def`、代入、複合代入、`if` / `elif` / `else`、`return`、`pass`
- `for i in range(count)`（開始は 0、上限は含まない）。ループ変数はそのループ内で使い、終了後には使わない
- `+ - * // % << >> & | ^`、単項の `- ~ not`
- `== != < <= > >=`、`and or`、数値の条件式 `a if condition else b`
- 引数を位置で渡す関数呼び出し。値として使う自作関数は、すべての経路で数値を返す

`import`、クラス、リスト生成、辞書、タプル、`while`、`break`、`continue`、`for ... else`、再帰、デコレーター、型注釈、デフォルト引数、キーワード引数、`range(start, end)`、`0 < x < 8` は使えません。比較の連鎖は `0 < x and x < 8` に分けます。

このバックエンドの引数用作業領域を守るため、引数の中に別の関数呼び出しを書けません。

```python
# Unsupported: tile(1, 3, max(0, s.kind))
kind = max(0, s.kind)
tile(1, 3, kind)
```

同じ関数名の再定義、共通関数と同じ名前、大小文字だけ違う関数名も禁止です。自作関数・引数・作業変数に `_` で始まる名前は使いません。

ループの添字にはループ内で代入せず、内側のループでも別の名前を使います。回数を求める関数は先に呼び出し、`count` などへ保存してから `range(count)` とします。上限の値はループの途中で変えません。

## 描画・音・制御 API

座標はドットではなく **文字単位** です。左上は `(0, 0)`。0 行はタイトルと面数、21 行以降は結果と確認に使うため、本編は原則 1〜20 行に収めます。各描画が画面端を越えないようにします。

| 呼び出し | 効果 |
| --- | --- |
| `tile(x, y, kind)` | `art.json` の 0〜7 番の 16×16 ドット絵を 2×2 文字で描く |
| `text(x, y, "READY")` | リテラルの文字列を横に描く |
| `letter(x, y, code)` | ASCII コードを 1 文字描く。例: 65 は A |
| `number(x, y, value)` | 000〜255 を 3 桁で描く |
| `sound(index)` | 0=移動、1=使用、2=成功、3=失敗の効果音 |
| `win()` | 面クリア。共通の成功演出と次の面への案内 |
| `lose()` / `lose("OUT OF STEPS")` | 失敗。メッセージは最大 31 文字 |
| `held()` | 最近スキャンした押下方向。通常 0=離した、1〜4=方向。イベント生成用ではない |
| `reschedule()` | 現在を基準に `tick()` の待ち時間を取り直す |
| `animate(ticks)` | 現在の状態を描画して待つ。待機中の入力は捨てる |
| `hold(ticks)` | 再描画せず現在の画面で待つ。待機中の入力は捨てる |
| `glide(ticks)` | 現在の状態を描いて待つ。次の操作は保持する |
| `min(a, b)` / `max(a, b)` | 符号なしバイト値の小さい方／大きい方 |

ゲームの終了時に成功／失敗用の音もランタイムが鳴らします。長い音を重ねて出すのではなく、単音の優先順位を考えます。`held()` の実装上は決定や複数キーの状態も返り得るため、方向を使うなら 1〜4 の範囲を明示して扱います。

## 共通の補助関数

補助関数も機械語に変換されます。使った関数だけがリンクされます。

| 関数 | 契約 |
| --- | --- |
| `move(pos, action, width, height)` | 一次元の盤面位置を上下左右に移す。外周では元の位置を返す。壁判定はゲーム側 |
| `grid(width, height, left, top)` | `b` の内容を `tile()` として並べる。要素数と画面範囲は呼び出し側で守る |
| `pointer(pos, width, left, top)` | 位置に `>` を描く |
| `box()` | `b[0:64]` を 8×8 の外壁=1、内側=0 で初期化 |
| `rand()` | `s.seed = (s.seed * 5 + 1) & 255` で再現可能な乱数を返す。先に seed を初期化 |
| `distance(a, b)` | 8 列の盤面上のマンハッタン距離 |
| `ringx(i)` / `ringy(i)` | 共通の 8 方向円配置の描画位置。i は 0〜7 |
| `ray(pos, direction)` | 8×8 盤面で隣へ進む。盤外は 255。方向の定義は `native/support.py` を参照 |
| `digits(x, y, value)` | 2 桁用の表示。0〜99 を渡す |

既存作品専用の `buttons()`、`stamp()`、`face()`、`flip()`、ランキング・パスワードなどは devkit 1 の共通 API に含みません。作品固有のアセットやランタイムが必要な機能を推測で呼ばないでください。

## メモリ上限

`build/layout.json` を確認します。コード・固定データは `$0300` から `$3000` の手前まで、画面バッファは 768 バイト、PCG は 256 バイト、スタック予約は 512 バイトです。状態と関数ローカルのスロットは合計 256 未満に制限します。長い文字列、大量の面データ、重複する関数はコード領域を圧迫します。制限を超えた場合は配置上限を緩めず、設計かデータを小さくします。
