# JR-100版 RELIC DIVE 開発資料

## 実装

ゲームはMB8861Hの機械語です。JR-800版の16ビット演算はA/Bの加減算と桁上がり・ゼロ判定へ置換し、乗算はソフトウェアで行います。インデックス加算にはMB8861HのADXを使用します。CPU命令の互換層やJR-800のLCDドライバーは含めません。

ソースは`src/`のモジュールを結合してアセンブルします。結合処理は命令の変換やコード生成をせず、命令はすべて編集可能なJR-100用ソースに置かれています。`check_layout.py`が配置上限とPCG枠数を検査します。

## メモリ

| 領域 | 用途 |
| --- | --- |
| `$0300–CODE_END` | ゲームコード、文字列、PCG初期データ |
| `CODE_END–$2FFF` | コード配置の余裕 |
| `$3000–$32FF` | 完成画面のRAMバッファー（768バイト） |
| `$3300–$33FF` | ゲーム状態と生成処理の変数 |
| `$3400–$37FF` | 64×32マスの地形、1マス4ビット（1,024バイト） |
| `$3800–$38FF` | 探索済みマスク、1マス1ビット（256バイト） |
| `$3900–$39FF` | 現在の視界、1マス1ビット（256バイト） |
| `$3A00–$3AFF` | 敵32枠×8バイト |
| `$3B00–$3B5F` | 品物32枠×3バイト |
| `$3B80–$3BFF` | 呼び出し元のゼロページ退避 |
| `$3C00–$3CFF` | PCGの退避領域 |
| `$3D00–$3D6F` | 区画配列、入力、描画などの一時変数 |
| `$3D80–$3D86` | 呼び出し元のSP・CCR・VIA退避 |
| `$3E00–$3FFF` | スタック予約512バイト |
| `$C000–$C0FF` | ハードウェアPCG（31文字使用） |
| `$C100–$C3FF` | ハードウェアVRAM |

一時変数としてゼロページ`$0080–$00F7`も使います。頻繁に参照する変数を`$00B0–$00F7`へ置き、直接アドレス命令でアクセスします。呼び出し元の`$0080–$00FF`は従来どおり退避・復元します。RAMは`$3FFF`までで、増設RAMを必要としません。正確なコードサイズと終端は`build/layout.json`に出力します。

地形の偶数Xは下位ニブル、奇数Xは上位ニブルです。地形値は0=壁、1=床、3=階段、4=遺物、5=隠し壁、6/7=未発見のダメージ/毒罠、8/9=発見済みの罠です。地形の値と探索・視界を分離し、品物と敵は疎な配列で持ちます。

## 描画

`RENDER_FRAME`は768バイトのRAMバッファーだけに描画し、消去・地形・品物・敵・主人公・文字の合成を終えてから`PRESENT`へ進みます。転送はVRAMと比較し、違う文字だけを1回書き込みます。同じ画面の再描画ではVRAMへの書き込みは0回です。メニュー・調査画面にも同じ仕組みを使い、短くなった文字列や移動前の主人公が残らないようにしています。

バッファーを標準16KB内に確保するため、単一階の配列走査をXレジスターで行う処理へ整理し、使用されない16ビットZ判定を除去しました。地形・ビット配列の行アドレス表も直接計算へ置き換えています。マップサイズ・品物生成・スタック予約・BREAK復帰用の退避領域は維持しています。

旧版の完成画面30ケース（10モード×3位置）とのハッシュ一致、合成中のVRAM不変、差分数と書き込み数の一致、同一セルへの二重書き込みがないことを検査します。全768文字が変わる場合の転送は20,374サイクル（894kHz換算で約22.79ms）。画面の生成中は旧画面を保持します。垂直同期には合わせていないため、転送中のスクロールの継ぎ目が実機で見えないことまでは保証していません。

## 移動処理の高速化

地形描画は各マスで`CELL`を呼ばず、行頭で求めた地形ポインター・探索ビットを順に進めます。未探索の連続した空白はまとめて処理します。奇数位置からのスクロールやバイト境界を含む99画面を、独立した圧縮データの読み出し結果と照合しています。迷宮画面では、後で全マスを上書きする地形部分の事前消去を省きます。

視線の経路は従来と同じBresenham判定を291バイトの表へ事前計算しました。`make_sight_rays.py`で`src/sight_rays.inc`を再生成できます。判定中の地形読み出しはRAM画面バッファーの先頭176バイトへ必要な分だけ記憶し、同じマスを何度も復号しません。画面合成時にはその領域も上書きされます。位置も地形も変わらないターンは視界を再利用し、地形書き込み時は必ず再計算を要求します。固定乱数の200地形で、旧来の視線ルール・探索済みマスク・新規発見数との一致とキャッシュの無効化を確認します。

入力ポーリングは視界・敵・描画の処理単位で行い、各マスや空の敵枠ごとの重複を除きました。敵の検索も配列を順に読み進めます。VRAM転送中は割り込みを禁止したままSPを読み出しポインターとして一時利用し、`PULA/PULB`で2文字ずつ比較します。この区間では呼び出しやスタックへの書き込みを行わず、終了前に元のSPを復元します。検証コアはこの区間のSP範囲と割り込み禁止を別に検査し、通常の呼び出しスタック使用量と区別して記録します。

変更前のコミット`bd182f1`と同じ3難易度の入力列で、クリア時の階・ターン・HP・食料は一致しています。最大通常処理は約481.88msから約195.02msへ約60%短縮しました。前段階の約323.66msからも約40%の短縮です。全ターンを100ms以下にする目標には届いていません。数値は894kHz換算のコア測定値で、実機での体感測定ではありません。

## パッド入力の根拠

ネット上の説明や古いエミュレーター実装より、実機で動作する既存プログラムの処理を優先しています。

- inufuto氏のASCEND：`LDAA $CC02`後にbit 0、1、2、3、4を検査し、非ゼロなら対応する操作を設定します。これらは右・左・上・下・ボタンです。別の初期判定は読み値`$FF`を未接続として扱います。
- STAR FIRE：`LDX #$CC02`でポートのアドレスを作り、ゼロページのポインターを介して読み、`$1F`で下位5ビットを取り出します。
- 現在のJR-100エミュレーターも、`$CC02`を押下時1、無入力`$00`で実装しています。

移植版では`$FF`を未接続として除外し、下位5ビットを使用します。極性の自動判定や校正画面はありません。キーボードはVIAの9行を走査し、2回一致した値を採用します。PB5のPCG選択を維持し、パッドをキーマトリクスへ変換するエミュレーター設定には依存しません。

`tests/reference_inputs.py`は手元に参照プログラムがある場合だけ、該当する命令列とSHA-256を確認します。参照プログラムやROMそのものは同梱しません。

## 追加した敵と魔法

NetBSD版Rogueの[敵一覧と能力](https://github.com/NetBSD/src/blob/trunk/games/rogue/monster.c)、[特殊攻撃](https://github.com/NetBSD/src/blob/trunk/games/rogue/spec_hit.c)、[品物一覧](https://github.com/NetBSD/src/blob/trunk/games/rogue/object.c)を参照して、JR-100用アセンブリで効果を実装しました。Cソースの移植ではなく、数値や持続時間はRELIC DIVE向けに調整しています。

- VAMPIRE：接触攻撃時に1/4で最大HPを1減らす。下限8。敵種13、PCG26。
- DRAGON：見える縦横の直線上への炎。攻撃力5、壁で遮断。敵種14、PCG27。
- NYMPH：未装備の持ち物を1個だけ盗み、逃走。敵種15、PCG28。元の持ち物盗難を本作の逃走処理へ組み込み、盗んだ品物の回収は行わない。
- EXTRA HEALING：HP全回復と毒の解除。
- HOLD MONSTERS：使用時に見えている敵を、使用ターンを含む6ターン停止。既存の敵レコードの未使用byte7を残り時間に使う。
- AGGRAVATE MONSTERS：全敵の記憶している追跡先を現在地に更新し、停止時間を解除。

薬4外見・巻物4外見をそれぞれの分類内でシャッフルします。識別ビットは1バイトの8ビットすべてを使用し、識別配列を5から8バイトへ拡張しました。外見IDは既存2〜6と新規14〜16、対応する識別スロットは0〜7です。装備種数は変更していません。

迷宮は48×32から64×32へ拡大しました。地形と2枚のビットマスクは計1,536バイトです。初期食料と回復量は維持しています。通常の品物はEASYで16〜23個、NORMAL/HARDで12〜19個を生成し、それぞれを重み付きで独立抽選します。食料6/32、薬8/32、巻物8/32、武器3/32、防具3/32、金3/32、杖1/32です。薬・巻物・装備は分類内で等確率で、階による装備の固定強化を廃止しました。食料も最低個数を保証せず、重複や欠落を許します。原作のランダム生成の考え方を取り入れ、数量・比率は本作の食料回復量と64×32マップに合わせた独自調整です。

杖と指輪は、既存の薬・巻物の8ビット識別枠に追加せず、各1種類の既知の品物としています。杖はkind17〜20で残り3〜0回を表し、床・持ち物・破棄・盗難の既存レコードで回数を維持します。視界内の指定した敵に8ダメージを与え、既存の撃破・レベルアップ処理を使います。調査カーソルを使うため、ターゲット選択中はターンが進みません。`G_WAND_SLOT`は`$3D6E`に置き、発射または取り消しで解除します。

指輪はkind21（外れた状態）／22（装着中）で表し、装着中も持ち物1枠を使用します。装着は1個までで、別の指輪を装着すると旧指輪を外します。食料がある時の奇数ターンは消費を省き、偶数ターンに消費します。破棄時はkind21へ戻し、NYMPHはkind22を飛ばして盗みます。杖も通常品物の抽選に含め、指輪は4階以降、各階1/16の確率で最大1個配置します。NetBSD版は品物と指輪の種類をランダムに選びますが、本作の指輪は遅消化のみなので、序盤の確定入手を避ける独自調整です。

`make_manual_images.py`は組み立て済みBINのPCGを読み、未使用の上り階段を除く30枚の64×64 PNGを`images/`へ生成します。READMEの図鑑はこの画像を使います。拡大は各ドットを8×8ピクセルへ複製し、ROMの文字画像は含めません。

メインメニュー・持ち物・品物操作・難易度選択は共通の`WRAP_CURSOR`で上下に循環します。先頭から上で末尾、末尾から下で先頭へ移ります。`BACK`のある一覧は先頭から上→決定で戻れます。キーボードとパッドの16ケースで循環・BACK・ターン不変を確認します。

移動キーは`QWE / ASD / ZXC`、待機は`S`、メニュー上下は`W/X`です。キーマトリクスは修正済みエミュレーターの`web/keymap.js`へ照合しました。SPACEはrow8 bit1、RETURNはrow8 bit3、BREAKはCTRL+C（row0 bit0とbit4）で、単独Cは右下へ移動します。

## 検証の区分

- **静的検査**：配置上限、全命令のコードとサイズを修正済みエミュレーターの命令表へ照合。
- **実行検査**：実際のゲームBINを標準16KB設定のC++コアで実行。戦闘、品物、8方向入力、視界、罠、画面端、長押し停止を確認。
- **地形検査**：固定した乱数種1〜1,000を4プロセスへ分割し、各難易度・深さの接続と配置を検査。
- **攻略探索**：固定したタイトル待機回数で初期乱数を再現し、独立した複数の攻略条件を並列探索。探索用の使い捨てコアでは、通常プレイ画面の描画だけを省略して高速化。ゲーム進行とメニュー入力は実際の機械語を実行する。
- **クリア受け入れ検査**：保存した入力列を新しいコアで再生。通常画面の描画も実行し、冒険開始後のRAM・レジスターの書き換えとチェックポイント復元を禁止。結果と処理時間を記録する。
- **画面確認**：手元のROMを使ったエミュレーターのフレームバッファーをPNGへ出力し、文字・PCG・メニュー・スクロールを確認。
- **実機**：この移植版自身のロード・表示・入力は未検証。既存ゲームの実機動作報告から、この移植版の実機動作を保証するものではない。

探索用のチェックポイントはCPUレジスター・フラグ、RAM、PCG/VRAM、VIAの内部時計を含めます。CPUとVIAを中心に実行し、不要なホストの音声生成・画面生成は省略します。BASICへの復帰はゲームの受け入れ条件には含めません。

## 測定結果（2026-09-09）

コード・定数は11,515バイト、終端は`$2FFB`（終端を含まない）。地形関連は1,536バイト、PCGは31文字で、64×32マス・隠し通路・2種類の罠・指輪・杖を残して標準16KBに収まりました。コード領域の空きは5バイト、PCGの残りは1文字です。PRGのロード先`$0300`と内容が検証用BINに一致することも検査します。

固定した1,000種の地形を4プロセスで検査し、接続・階段到達・配置制限をすべて通過しました。異なる地形は999種、部屋数は6〜8、隠し通路がある地形は586種でした。地形生成の最大は2,962,070サイクル（894kHz換算で約3.31秒）です。

品物の組み合わせは992通りで、全種類が出現しました。食料のない階は27、杖のない階は578、薬・巻物の重複がある階は943でした。指輪は対象647階中28階に出現し、1〜3階には出現しませんでした。この固定標本の実測比率は設計確率そのものではありません。

保存入力を3プロセスで並列再生し、3難易度すべてで遺物取得を確認しました。描画省略なし、冒険開始後のホストによる状態変更は0回です。

| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| EASY | 4 | 5 | 780 | 1,132 | 169ms | 2.93秒 |
| NORMAL | 2 | 10 | 1,438 | 2,164 | 194ms | 2.55秒 |

移動したターン（階生成を除く）の中央値はEASY 152.45ms、NORMAL 156.02ms、HARD 157.57ms、95パーセンタイルはそれぞれ162.39ms、171.01ms、184.04msです。スクロールを伴う移動の中央値は153.05ms、157.27ms、158.04msでした。100ms未満の移動は各難易度で0.2%、0.1%、0.1%にとどまります。入力列・画面の状態に依存する測定であり、全状況の上限ではありません。

数値は実行サイクルを894kHzで換算した値で、実機計測ではありません。リプレイ中の最大スタック使用量は16バイト（予約512バイト）。リプレイ検証自体は3プロセスで約5.3秒でした。クリア経路は全地形・品物の正体を読み取った探索によるもので、初見の人間にとっての難易度評価ではありません。

## 階生成中の表示

新規ゲーム・下降で共通の生成処理へ入ると、中央の3行×16文字に`[ BUILDING 1/4 ]`を表示します。地形・品物・敵・仕掛けの開始に合わせて1〜4へ進みます。各段階の時間は均等ではなく、残り時間の割合を表しません。完成時は通常の描画で消えます。乱数やゲーム状態を変更せず、待機時間も追加しません。領域初期化を連続書き込みへ整理して表示分のコード容量を確保しました。
