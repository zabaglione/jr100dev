# JR-100 PCG Clock

JR-100のPCGへ数字0-9とコロンを登録し、画面中央付近に`HH:MM:SS`形式の時計を表示するサンプルです。時刻は`12:00:00`から始まり、24時間制で約1秒ごとに更新されます。

## ビルド

リポジトリのルートで次を実行します。

```sh
make -C samples/pcg_clock
```

成功すると、次のファイルが生成されます。

- `build/pcg_clock.prg`
- `build/pcg_clock.bin`
- `build/pcg_clock.json`
- `build/pcg_clock.map`

JR-100エミュレーターまたは実機へ`build/pcg_clock.prg`をロードし、`A=USR($0300)`で開始します。時計は無限ループするため、呼び出し元へは戻りません。

## 実装内容

- PCG領域`$C000-$C0FF`へ32文字分、合計256バイトを転送します。
- スロット0-9を数字、スロット10をコロンとして使い、未使用の21スロットはすべてゼロです。
- 数字データは`tools/pcg_editor/core.js`を正本とし、Makefileが`src/pcg_data.inc`を自動生成します。
- VIA DDRB (`$C802`) とORB (`$C800`) の既存値を保持しつつPB5だけを出力かつHighにし、ユーザー定義文字面を選択します。
- 表示には数字コード`$80-$89`とコロンコード`$8A`を使います。
- 使用命令はMB8861H/6800系に限定しています。

## 待ち時間の概算

`clock_hz = 894000`を前提に、内側ループを`$DA37`回、外側ループを2回実行します。6800標準のサイクル数で`DEX`と`BNE`を各4サイクルとして数えると、待ちサブルーチン本体は893,833サイクルです。呼び出し、通常時の時刻更新、再描画を含む1更新は約894,013サイクル、約1.000015秒です。

繰り上がり時は数十サイクル余分にかかります。CPUクロック誤差や割り込みを除いたソフトウェア上の概算では、時計は1日あたり約1-2秒遅れます。
