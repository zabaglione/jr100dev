# サンプルコードのルール

## 読み方

サンプルは難易度順に読むことを想定しています。

1. `hello`: エントリポイントとVRAMへの直接書き込み
2. `counter`: 標準マクロと単純な制御構造
3. `io_demo`: 画面、キー、簡易ビープ
4. `key_display`: VIAの直接制御
5. `multi`: 複数ソースのリンク
6. `pcg_clock`: PCG、PB5、サイクル計測
7. `maze`: 複数モジュール、ワーク領域、入力、スクロール

## ディレクトリ規約

各サンプルは`samples/<name>/`に置き、最低限次を含めます。

- `README.md`: 何を学ぶ例か、ビルド方法、実行方法、ハードウェア上の注意
- `Makefile`: リポジトリルートから`make -C samples/<name>`でビルド可能
- `main.asm`または`src/main.asm`: `$0300`から開始するエントリ
- `build/`: 生成物専用。ソースとしてコミットしない

## 実装ルール

- サンプルは一つの主題を持たせ、複雑な例ではREADMEに入口となるファイルと主要ラベルを記載します。
- 使用するI/Oアドレス、ワーク領域、無限ループの有無をREADMEに記載します。
- 6809命令を使わず、MB8861Hで有効な命令だけを使用します。
- 実行中にBASICへ戻らない場合は、そのことを実行手順へ明記します。

## 確認手順

1. `make -C samples/<name> clean all`が成功する。
2. `.prg`、`.bin`、必要に応じて`.json`と`.map`が`build/`へ生成される。
3. マップ上のエントリ、コード、データ、BSSが意図した範囲にある。
4. エミュレーターで開始方法と期待動作を確認する。
5. 複雑なサンプルには`tests/integ`またはサンプル内テストを追加する。
