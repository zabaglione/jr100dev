# JR-100開発ルール

このディレクトリは、JR-100向けプログラムを書く前に確認するルールの入口です。サンプルが動いても、CPU命令、I/Oレジスタ、書き込み順を誤ると実機やエミュレーターで挙動が変わるため、機種固有の制約をコードより先に整理しています。

## 読む順序

1. [`hardware.md`](hardware.md): CPU、クロック、メモリ、VRAM、PCG、VIAの基本
2. [`assembly.md`](assembly.md): 使用可能な命令、エントリポイント、命名、I/O実装上の注意
3. [`samples.md`](samples.md): サンプルの読み方、追加方法、確認項目

## 最重要ルール

- CPUはMB8861Hで、MC6809ではありません。
- 6800系標準命令とMB8861H独自拡張だけを使用します。
- プログラムの標準エントリは`$0300`です。
- VRAM、PCG、VIAは通常RAMではなく、書き込みにハードウェア上の意味があります。
- 16bitタイマーなど、上位・下位バイトの書き込み順に意味があるレジスタはデータシートと実機仕様に従います。
- エミュレーターで動くだけで完了とせず、命令セット、メモリ範囲、生成されたマップを確認します。

## ルールと詳細資料の区別

`rules/`は新しいコードを書くときの判断基準です。`docs/`はアセンブラ、標準マクロ、PRG形式、個別サンプルの設計記録です。迷った場合は`rules/`を優先し、具体的な実装方法を`docs/`と`samples/`で確認してください。
